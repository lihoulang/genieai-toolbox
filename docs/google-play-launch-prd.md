# Google Play 上线前完善 PRD

文档版本：v1.0  
编写日期：2026-05-01  
适用项目：`uni-ai-starter`  
评估范围：当前仓库代码、基础配置、Google Play 官方上线要求

## 1. 背景

当前项目已经具备一个可演示的 AI 聊天产品雏形，核心能力包括：

- 文本对话
- 图片识别
- AI 绘画
- AI 视频
- 用户注册登录
- 会话管理
- 算力余额/签到

但从 Google Play 的提审标准看，当前项目仍属于 `MVP / Demo 可用`，还不属于 `可直接提审的正式商业版本`。

## 2. 当前结论

### 2.1 总体判断

不建议现在直接提审 Google Play。

如果以 `Demo 可跑` 为标准，当前完成度较高；如果以 `Google Play 可审核通过并可稳定上线` 为标准，当前完善度大约在 `40% - 50%`。

### 2.2 当前最核心的问题

当前阻塞点不在“功能数量不够”，而在以下四类：

1. 商店发布配置未完成
2. 隐私与账号合规未完成
3. 后端安全模型过弱
4. 稳定性与发布验证体系缺失

## 3. 代码现状证据

以下问题已经能从当前仓库直接确认：

### 3.1 Android/App 发布基础配置未完成

- `frontend/manifest.json:3` 的 `appid` 为空，说明 App 还没有正式包标识。
- `frontend/manifest.json` 只有非常基础的配置，没有看到完整的 `app-plus`、Android 打包、权限说明、图标、启动图、签名相关配置。
- `frontend/config.js:2` 仍然写死为 `http://uniai.mastermath.cn`，正式上架必须改为 HTTPS-only。

### 3.2 账号与数据安全不足

- `backend/main.py:215-222` 登录仅返回 `user_id`，没有 token / session / refresh token。
- `frontend/pages/login/login.vue:51-53` 登录后只把 `user_id` 存到本地。
- `backend/main.py:227-365` 多个接口直接按 `user_id` 或 `conv_id` 操作，没有鉴权与资源归属校验。
- `backend/main.py:129-130` 密码使用单次 SHA-256，未使用 bcrypt / Argon2 等专用密码哈希。
- `backend/main.py:105-111` CORS 对所有来源开放。

### 3.3 业务逻辑存在明显风险

- `backend/main.py:414-422` 读取了用户余额后，直接把 `current_balance` 写死成 `100`，实际余额校验无效。
- `backend/main.py:461-462` 对话发送前先扣费，但外部模型失败时没有补偿逻辑。
- `backend/main.py:316-333` 会话置顶/删除接口没有校验当前用户是否拥有该会话。

### 3.4 合规能力缺失

- 仓库内没有隐私政策文档、账号删除说明、服务条款。
- `frontend/pages/profile/profile.vue:47-57` 只有深色模式和退出登录，没有“删除账号 / 注销账号”入口。
- 当前图片上传能力存在于 `frontend/pages/index/index.vue:241-254`，但没有权限用途说明、隐私披露、第三方数据处理告知。
- 当前支持 AI 生成文本/图片/视频，但没有用户举报或标记不当 AI 结果的入口。

### 3.5 测试与发布验证缺失

- `frontend/package.json:6-8` 没有可用测试脚本。
- 仓库内没有自动化测试文件。
- 本地尝试使用 FastAPI TestClient 做烟测时，发现测试依赖未补齐，说明发布前验证链路尚未成型。

## 4. Google Play 官方要求摘要（与本项目直接相关）

以下要求基于 Google 官方文档，且与本项目直接相关：

1. 新应用必须以 Android App Bundle (`.aab`) 形式发布。
2. Google Play 对 target API level 有持续要求；截至 2026-05-01，面向手机和平板的新应用需满足官方 target API 要求，当前应以 `targetSdkVersion 35 (Android 15)` 为基线。
3. 如果应用收集、处理或共享用户数据，需要填写 `Data safety`。
4. 如果应用处理敏感用户数据，通常需要提供公开可访问的 `Privacy Policy`。
5. 如果应用允许创建账号，Google Play 要求提供 `账号删除能力`，包括应用内删除入口，并提供配套删除说明/链接。
6. 使用 AI 生成内容的应用，需要提供让用户举报或标记不当 AI 生成内容的能力。
7. 某些开发者账号在发布到生产环境前，必须先完成指定的测试要求；如果你的账号属于 `2023-11-13` 之后创建的个人开发者账号，需要重点核对当前的 closed testing 门槛。

说明：

- target API 以提审当日 Play Console 要求为准，但基于当前官方文档，项目应按 API 35 规划。
- 如果你的开发者账号是公司账号，不一定受“个人账号生产前测试门槛”限制，但仍需要核对 Play Console 当前提示。

## 5. 上线目标

目标不是“先把包传上去试试”，而是形成一个可通过审核、可灰度、可回滚、可持续运营的 `Google Play v1.0 正式版`。

### 5.1 v1.0 上线目标

- 通过 Google Play 审核
- 具备完整隐私合规材料
- 核心链路稳定可用
- 账号安全达到基础商用标准
- AI 能力可控，能处理审核与用户投诉风险

### 5.2 v1.0 非目标

以下能力不作为本次提审前的必须项：

- 完整商业化付费体系
- 多语言国际化
- 复杂运营活动系统
- 高级推荐与增长体系
- 企业级后台管理系统

## 6. 提审前必须完成（P0）

以下事项全部建议作为 `提审阻塞项`，未完成不建议提交。

### P0-1. 完成 Android 正式发布配置

#### 目标

让应用具备最基本的正式打包与分发条件。

#### 必做项

- 确定正式 `applicationId / appid / 包名`
- 配置 Android 正式签名
- 确认应用名、图标、启动图、版本号、版本编码
- 补齐 `manifest.json` 的 App 发布配置
- 产出正式 `.aab`
- 核对目标 API 与 Android 权限声明
- 明确相册/拍照上传在 Android 端实际申请的权限及其用途文案
- 全量 API 改为 `HTTPS`

#### 当前差距

- `frontend/manifest.json:3` 为空
- `frontend/config.js:2` 仍为 HTTP

#### 验收标准

- 可以稳定打出 release AAB
- 真机安装后首启、登录、聊天、上传图片都正常
- 不出现 cleartext traffic、证书或域名错误

### P0-2. 完成账号系统安全改造

#### 目标

把当前“只靠 user_id”的弱鉴权方案改成正式可上线方案。

#### 必做项

- 引入 access token 鉴权
- 关键接口改为基于 token 获取当前用户，不允许前端直接指定任意 `user_id`
- 所有 conversation/message/balance 接口增加资源归属校验
- 密码存储改为 `bcrypt` 或 `Argon2`
- 增加登录失效、退出登录、token 过期处理
- 增加基本的防刷与异常请求保护

#### 当前差距

- `backend/main.py:215-222`
- `backend/main.py:227-365`
- `backend/main.py:129-130`
- `frontend/pages/login/login.vue:51-53`

#### 验收标准

- A 用户不能读取/删除/修改 B 用户的数据
- 密码数据库泄露时不能被低成本直接还原
- 未登录状态不能调用用户私有接口

### P0-3. 修复核心业务逻辑漏洞

#### 目标

避免上线后出现错误扣费、越权操作、余额异常等直接伤害用户体验的问题。

#### 必做项

- 修复对话余额校验逻辑，不能再写死 `current_balance = 100`
- 扣费逻辑改为事务化或失败补偿
- 会话删除、置顶、历史读取增加归属验证
- 对第三方模型失败、超时、限流做明确提示与补偿
- 对视频/图片长任务增加任务态管理，不阻塞请求线程

#### 当前差距

- `backend/main.py:414-422`
- `backend/main.py:461-462`
- `backend/main.py:316-333`

#### 验收标准

- 用户余额不足时不能继续成功发起能力调用
- AI 服务失败时不会产生错误扣费
- 会话越权操作全部被拒绝

### P0-4. 完成隐私政策、Data safety、账号删除合规

#### 目标

满足 Google Play 最核心的账号与用户数据合规要求。

#### 必做项

- 编写并上线公开可访问的 `Privacy Policy`
- 在应用内增加隐私政策入口
- 梳理并填写 Play Console 的 `Data safety`
- 明确披露：
  - 账号信息收集
  - 聊天内容处理
  - 图片上传处理
  - 第三方模型服务商处理路径
  - 数据是否存储、保存多久、是否可删除
- 提供应用内 `删除账号` 功能
- 提供账号删除后的数据删除说明
- 在商店页或支持页提供账号删除配套说明链接

#### 当前差距

- 仓库无隐私政策文件
- `frontend/pages/profile/profile.vue:47-57` 无删除账号入口
- `backend/main.py` 无删除账号接口/数据清理逻辑

#### 验收标准

- 用户可在 App 内发起账号删除
- 删除流程清晰、可追踪、可执行
- Play Console Data safety 可据实填写

### P0-5. 完成 AI 内容合规与风控

#### 目标

降低 AI 生成内容导致审核拒绝、用户投诉或政策命中的风险。

#### 必做项

- 为 AI 文本/图片/视频结果增加 `举报/标记不当内容` 入口
- 建立基础敏感词与高风险请求拦截
- 对暴力、色情、自残、违法等高风险提示词做兜底限制
- 对生成失败、违规拒答、审核拦截给出明确反馈
- 在隐私政策或服务条款中说明 AI 输出不保证绝对准确

#### 当前差距

- `frontend/pages/index/index.vue` 目前只有复制和删除消息，没有举报/反馈入口

#### 验收标准

- 每条 AI 结果都可反馈或举报
- 明显违规请求能被拦截或拒绝
- 审核人员能清楚看到内容治理机制

### P0-6. 完成稳定性验证与回归测试

#### 目标

确保首次提审不是“边上线边找 bug”。

#### 必做项

- 建立最小自动化烟测
- 覆盖注册、登录、建会话、发消息、读历史、上传图片、退出登录
- 补齐测试依赖与测试命令
- 增加后端异常日志与关键业务日志
- 真机回归 Android 主流机型与不同网络场景
- 准备发布前 checklist

#### 当前差距

- `frontend/package.json:6-8` 无测试能力
- 仓库无自动化测试

#### 验收标准

- 发布前可一键跑烟测
- 关键链路全部手工回归通过
- 发布后能快速定位线上问题

### P0-7. 完成商店提审物料与 Play Console 配置

#### 目标

避免“代码好了，但因为资料不完整被卡住”。

#### 必做项

- 应用名称、副标题、完整描述、简短描述
- 高清图标、Feature Graphic、截图
- 应用分类、标签、内容分级
- 联系邮箱、隐私政策链接、支持链接
- 测试账号与审核说明
- 是否包含广告、账号系统、用户生成/AI 生成内容等声明
- 若账号类型要求 closed testing，先完成测试闭环再申请 production

#### 验收标准

- Play Console 所有必填项一次填完
- 审核员拿到测试账号即可完整体验关键路径

## 8. 建议的上线版本范围

为了尽快提审，建议本次 v1.0 范围收紧，不要追求“大而全”。

### 建议保留

- 注册/登录
- 文本聊天
- 基础会话管理
- 图片识别
- 基础算力余额显示

### 建议谨慎上线

- AI 视频

原因：

- 成本高
- 生成时间长
- 容易超时
- 更难解释失败原因
- 对审核体验不友好

如果时间紧，建议 `v1.0 先下线视频生成`，等稳定性、任务队列和扣费补偿成熟后再在 `v1.1` 放开。

### 建议可暂缓但保留入口文案规划

- 邀请裂变深度玩法
- 更复杂的发现页内容
- 高级 Markdown 能力

## 10. 推荐排期

### 第一阶段：提审阻塞项清理（优先级最高）

建议先做：

1. HTTPS + AAB + 包名/签名/版本配置
2. token 鉴权 + 密码哈希升级 + 资源归属校验
3. 隐私政策 + Data safety + 删除账号
4. 余额/扣费/越权逻辑修复

### 第二阶段：提审稳定性完善

然后再做：

1. AI 结果举报入口
2. 基础内容风控
3. 自动化烟测
4. 真机回归和商店物料整理

## 11. 对你当前项目的最终建议

如果目标是“尽快上架，但提高一次过审概率”，建议执行策略如下：

1. 本次不要追求把所有功能都做成完整版，先把 `安全、合规、打包、稳定性` 做扎实。
2. 把 `AI 视频` 从首发范围里降级处理，优先保证文本聊天和图片识别稳定通过。
3. 先把账号删除、隐私政策、Data safety、AI 举报入口这四件事补齐，否则审核风险很高。
4. 先修掉后端鉴权和余额逻辑，否则即使过审，正式上线也会很快暴露事故。
